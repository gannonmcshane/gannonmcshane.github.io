Terminology

Directory Services

Directory services map the names of network resources to their corresponding network addresses. These resources can include printers, user accounts, phone numbers, VoIP devices, and much more. A directory service is a shared infrastructure used to store, manage, and organize this information. Each resource in a directory service is treated as an object, and the information about that object is stored as a collection of attributes linked to it. In short, directory services store information about users and resources, such as passwords, user preferences, IP addresses, and other device details. One well-known directory service is the Domain Name System (DNS), which translates domain names into IP addresses. The Lightweight Directory Access Protocol (LDAP) is a protocol used to look up information and devices on a network. LDAP is useful because it is vendor-neutral and works across different directory services. For example, if a directory service stores a list of printers and files in its database, LDAP makes it possible to find a specific printer or file within it. Another type is the key file directory service, which stores each user's password in hashed form along with a list of the groups that user belongs to.

Active Directory

Active Directory Domain Services (AD DS) is a server role within Active Directory that lets administrators store and manage information across a network ("What Is Active Directory," n.d.). For example, instead of keeping one long, disorganized list of users, a large company can use Active Directory to organize them into groups such as users in analytics or users in the engineering department. Active Directory stores user data such as names, passwords, email addresses, and phone numbers. AD DS allows only users in the database to access network information, and it can restrict certain parts of the network to those with administrator credentials. One reason Active Directory stands out is that it is simple for administrators to use while also strengthening an organization's security. One of AD's main functions is giving administrators control over how users in their organization gain access. It also saves time, since users can sign in and reach the resources they are permitted to use without an administrator granting permission manually each time. Because Active Directory is scalable, customizable, and lets administrators manage user authorization from a single system, it is a superior choice for organizations ("What Is Active Directory," n.d.).

Server Roles

DHCP

Dynamic Host Configuration Protocol (DHCP) assigns IP addresses to devices on a network so they can communicate using IP. DHCP handles this process automatically, rather than requiring an administrator to manually assign an IP address to every device (Gillis, n.d.). When devices are moved to a new location, DHCP assigns them new IP addresses. The process begins when a client sends out a DHCP discover message, and the DHCP server responds by offering an available IP address. The client then sends a request for that address, and the server acknowledges it, completing the sequence. DHCP also gives clients other TCP/IP configuration information, including DNS server addresses, subnet masks, and default gateway addresses. Since DHCP automatically assigns new IP addresses when devices move, there is no need for DHCP servers at multiple sites.

DNS

The Domain Name System (DNS), as the name suggests, is a naming service. It translates domain names into IP addresses so devices can find one another (Fortinet, n.d.). This also allows users to reach a website by typing its name instead of remembering its IP address. DNS is important because it allows devices to communicate across a network, which is why DNS is included at every location in the network topology.

WSUS

Windows Server Update Services (WSUS) is used to manage and distribute the updates and fixes released through Microsoft Update. WSUS is an important tool for securely managing and installing updates on Microsoft products (SolarWinds, n.d.). Multiple WSUS servers can be deployed at once so the workload is shared between them, and the number of WSUS servers a company uses usually depends on how many client computers it has. Administrators can also configure WSUS to automate updates based on their preferences. WSUS is important because it keeps updates and fixes for Microsoft products running smoothly.

Proxy

A proxy server serves as a gateway between devices and the internet. It acts as an intermediary between users' devices and the websites they visit, which adds security to a private network (Fortinet, n.d.). A proxy server appears on the internet as its own computer, with an IP address separate from the end users' devices. A proxy can also be set up as a firewall or web filter for an additional layer of security. A proxy server is important because it helps manage traffic and security, which is why it is part of the corporate office topology.

SCM

Supply chain management (SCM) is a way for administrators to manage the flow of goods and data (Fernando, 2024). SCM covers the entire business process, starting with raw materials, moving through design, and ending with shipping the finished goods. SCM is crucial because it supports the business as a whole and the distribution of its products. SCM is only necessary at the corporate office because it involves managing the entire operation, which should be handled at the main site.

NLB

Network Load Balancing (NLB) distributes traffic across multiple servers within a cluster so that no single host is overworked, keeping the company running smoothly (Awati, n.d.). Because NLB reduces the strain on servers and network devices, it increases their reliability, making it vital for the corporate office.

RDP

Remote Desktop Protocol (RDP) is a protocol that allows someone to use a desktop computer from a separate location. This is beneficial because employees can access their work computer from a different device to edit files, open applications, and more. RDP also encrypts data, making it more secure (Cloudflare, n.d.).

AD

Active Directory (AD) is used to manage devices, users, and domains within a network, and it is valued for its strong identity and access management capabilities (SolarWinds, n.d.). For example, instead of keeping one long, disorganized list of users, a large company can use Active Directory to organize them into groups such as users in New York or users in the engineering department. Active Directory stores user data such as names, passwords, email addresses, and phone numbers. One reason AD is necessary at the corporate office is that it is simple for administrators to use and increases the organization's security.

Computer Usage and Restriction Policies

Legal notices and restriction policies are important because they tell users what to expect and give the company legal protection. A legal notice on a computer can help deter malicious users from accessing company systems. It also allows the company to monitor the data a user sends or processes without running into legal issues. Because the user has agreed to the notice, it can also protect the company from being sued.

NTFS is the Windows file system used to organize and store files. With files and shared folders, it's important to have the right security permissions in place. For example, one department may only need read permissions, while some folders may need to be kept completely private. The goal is to give employees enough access to do their jobs properly while granting the least amount of access necessary, a practice known as the principle of least privilege.

Security Guidelines

Server Security Policy

Last Update Status: Updated March 2024

Overview

Unsecured and vulnerable servers continue to be a major entry point for malicious threat actors. Consistent Server installation policies, ownership and configuration management are all about doing the basics well.

Purpose

The purpose of this policy is to establish standards for the base configuration of internal server equipment that is owned and/or operated by <TRI-Arrow Printing>. Effective implementation of this policy will minimize unauthorized access to <TRI-Arrow Printing> proprietary information and technology.

Scope

All employees, contractors, consultants, temporary and other workers at <TRI-Arrow Printing> and its subsidiaries must adhere to this policy. This policy applies to server equipment that is owned, operated, or leased by <TRI-Arrow Printing> or registered under a <TRI-Arrow Printing>-owned internal network domain.

This policy specifies requirements for equipment on the internal <TRI-Arrow Printing> network. For secure configuration of equipment external to <TRI-Arrow Printing> on the DMZ, see the Internet DMZ Equipment Policy.

Policy

General Requirements

All internal servers deployed at <TRI-Arrow Printing> must be owned by an operational group that is responsible for system administration. Approved server configuration guides must be established and maintained by each operational group, based on business needs, and approved by the InfoSec team. Operational groups should monitor configuration compliance and implement an exception policy tailored to their environment. Each operational group must establish a process for changing the configuration guides, which includes review and approval by InfoSec. The following items must be met:

  • Servers must be registered within the corporate enterprise management system. At a minimum, the following information is required to positively identify the point of contact:
  • Server contact(s) and location, and a backup contact
  • Hardware and Operating System/Version
  • Main functions and applications, if applicable
  • Information in the corporate enterprise management system must be kept up to date.
  • Configuration changes for production servers must follow the appropriate change management procedures
  • For security, compliance, and maintenance purposes, authorized personnel may monitor and audit equipment, systems, processes, and network traffic per the Audit Policy.

Configuration Requirements

  • Operating System configuration should be in accordance with approved InfoSec team guidelines.
  • Services and applications that will not be used must be disabled where practical.
  • Access to services should be logged and/or protected through access-control methods such as a web application firewall, if possible.
  • The most recent security patches must be installed on the system as soon as practical, the only exception being when immediate application would interfere with business requirements.
  • Trust relationships between systems are a security risk, and their use should be avoided. Do not use a trust relationship when some other method of communication is sufficient.
  • Always use standard security principles of least required access to perform a function. Do not use root when a non-privileged account will do.
  • If a methodology for secure channel connection is available (i.e., technically feasible), privileged access must be performed over secure channels, (e.g., encrypted network connections using SSH or IPSec).
  • Servers should be physically located in an access-controlled, secured environment.
  • Servers are specifically prohibited from operating from uncontrolled or unsecured cubicle areas.

Monitoring

All security-related events on critical or sensitive systems must be logged and audit trails saved as follows:

  • All security related logs will be kept online for a minimum of 1 week.
  • Daily incremental tape backups will be retained for at least 1 month.
  • Weekly full tape backups of logs will be retained for at least 1 month.
  • Monthly full backups will be retained for a minimum of 2 years.

Security-related events will be reported to InfoSec, who will review logs and report incidents to IT management. Corrective measures will be prescribed as needed. Security-related events include, but are not limited to:

  • Port-scan attacks
  • Evidence of unauthorized access to privileged accounts
  • Anomalous occurrences that are not related to specific applications on the host.

Policy Compliance

Compliance Measurement

The Infosec team will verify compliance to this policy through various methods, including but not limited to, business tool reports, internal and external audits, and feedback to the policy owner.

Exceptions

Any exception to the policy must be approved by the Infosec team in advance.

Non-Compliance

An employee found to have violated this policy may be subject to disciplinary action, up to and including termination of employment.

A honeypot is useful because it distracts cybercriminals from the real network, keeps them occupied, and reveals information about the methods they use (Bodnar, 2023). Windows & Linux Integration

Linux Server

A Linux server is simply a server that runs a version of the open-source Linux operating system (Hat, 2022). Its fully open-source nature is what keeps Linux low-cost and highly flexible. Linux is also a lightweight operating system, typically requiring only about 4 to 8 GB of disk space, and it is compatible with nearly every file type (Swain, 2023). One major advantage of Linux servers is their scalability, as they can handle large amounts of data and work well for large companies (LogicMonitor, 2023). They are commonly used for database management, web hosting, file sharing, and virtualization (Sisense, 2024).

Windows Server

Windows Server is a family of operating systems that includes applications and features built to support small to medium-sized businesses (SOLARWINDS, 2024). Some of its major features are Active Directory, DNS, DHCP, web and application servers, and WSUS (DeMeyer, 2022).

Linux and Windows Integration

The best way to integrate Linux and Windows at TRI-Arrow Printing is to have the Linux systems authenticate against Windows Active Directory (Vaughan-Nichols, 2010; Worthington & Keller, 2023). The System Security Services Daemon (SSSD) is the ideal tool for this. SSSD is highly configurable and works through PAM and NSS to handle authentication and user account information on Linux systems (Hat, n.d.). It is the best way to connect a Linux system to an identity provider, whether that is LDAP, Active Directory, or an identity management system. SSSD is a system service that supports both direct and indirect integration, and it allows a Linux system to access remote directories and authentication mechanisms. One key benefit is that SSSD caches credentials, so users can still authenticate and reach resources even when the client or the remote provider is offline (Hat, n.d.).

The Linux server roles at TRI-Arrow Printing should include print servers, web servers, and email servers (DeMeyer, 2022). Linux is well suited to these roles because it offers strong security and flexibility, and because it is open source. Its scalability also makes it a good fit for these workloads (LogicMonitor, 2023). Linux provides access control capabilities that let administrators restrict what user accounts can do (Swain, 2023). Another benefit of the open-source model is that anyone can find, report, and help fix bugs in the system (Hat, 2022).
